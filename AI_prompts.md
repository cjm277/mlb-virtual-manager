# AI Prompts

This file logs the prompts typed into the vibe coder while building MLB Virtual Manager. Secrets and API key values are never recorded.

Each phase section includes the phase name, the prompt typed, any follow-up prompts, and one sentence on what the first prompt was missing.

## Extra analysis (between Phases 8 and 9) - Win impact

- Prompt typed: "I want to test something before we move on to phase 9. This could take a while and that's fine, I'm happy to be patient. Across a sample of many games, can you try to predict the likelihood of our chosen (manager's) team victory based on the game plan I've constructed compared to what actually happened? I'm trying to put a numeric value (or at least a confidence range) on how what I've built here can drive more wins. It's fundamentally a regression type analysis. I'm trying to justify a claim that approaching baseball the way my app describes it could be genuinely better than what a (smart, but flawed) human coach could come up with. Make sense? Get after it."
- Follow-up prompt: "Can we be really clear? The analysis of value should be: would our predicted approach be analytically more likely to result in a win than the approach the manager actually used? The actual result or the end of season record is not the important consideration.  It should all be grounded in numbers. It feels to me like you are saying "oh this happened" too much. That's not the point. We're trying to make a model for wins. Does that make sense or am I just chatting shit?"
- Additional follow-up prompt: "Yes, run the experiment: build the lineup from the win model (platoon edge and rest days priced in), shrink the matchup score toward season quality, and re-score 150 games the same way."
- Additional follow-up prompt (sent while the vibe coder was working): "We're trying to win games here boys; let's do whatever we can to give this model real predictive value. We want to build a model that gives better predictions than a flawed human would. Got it? Keep that in mind while you work"
- Additional follow-up prompt: "Yeah let's add defence. I love the extra 1.5 wins but I'm trying to make this model truly valuable, and the game is played on offence and defence. Build the defence evaluation in and see if we can push that expected win total up"
- Additional follow-up prompt (sent while the vibe coder was working): "We should download more data if we need to in order to help with the defence evaluation. You can do that download, do it if its helpful."
- Additional follow-up prompt: "Well. Shit, that sounds like a lot of money. Either way let's verify value before we move into phase 9. Is the current model really worth 2.4 games per year? Verify the value of those wins in expectation. Let's make sure we have a solid factbase before I start making bold proclamations about this app's value."
- What was lacking after the first: The prompt did not say how to value a plan that was never played; the first draft fitted the model to game results and talked about what happened, and the follow-up made it an analytic win model (lineup and starters to expected runs to win probability, everything else held fixed) that compares our plan with the manager's using only pre-game numbers, with game results used only to check the model's probabilities are realistic. The additional follow-ups had code build the lineup from the win model, with every input chosen by out-of-sample prediction on 2026 data (pitch-type matchup detail dropped; rest days priced in win probability); on the same 150 games the plans moved from +0.2 to about +1.5 wins per 162 on the independent lens. Defense was then added from newly downloaded 2023-2026 position-by-position Outs Above Average, innings and catcher framing (prior seasons only, no look-ahead), with the rating and its weight chosen by data; the plans moved to about +2.4 wins per 162 (+1.8 to +3.0), and the run exposed and fixed a checker bug that flagged real negative stats as made up. The verification follow-up did not say what "verify" should test against; the vibe coder stress-tested the +2.4 on existing data with no new model calls. It re-scored the plans with data the optimizer never saw, checked each input's slope against real 2026 results (with an August-September hold-out), replayed full seasons so moving a starter up a day is not counted as free, and widened the interval for model uncertainty. The verified figure is about +1.4 wins per 162 (honest range +0.5 to +1.9), worth roughly $11-17M a season to a single first-mover team at free-agent prices, or about $1-4M through playoff odds alone, and close to nothing in wins if every team adopted it (wins are zero-sum). See `evidence/tests/value_verification.md`.
